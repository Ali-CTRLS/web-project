# InjuryAssist — Patient-Doctor Injury Management Platform

## Project Overview

InjuryAssist is a clean, simple web platform that connects injured patients with doctors, manages injury assessments, appointment booking, and generates medical reports. The platform supports two user roles: **Patient** and **Doctor** (General & Specialized).

### Technology Stack

- **Backend**: Python Flask (lightweight, beginner-friendly)
- **Frontend**: Jinja2 Templates + Tailwind CSS (CDN — no build tools)
- **Database**: SQLite + Flask-SQLAlchemy (zero config, file-based)
- **Auth**: Flask-Login (simple session-based authentication)
- **File Encryption**: `cryptography` library (AES-256-GCM for report files)
- **Forms**: Flask-WTF (CSRF protection + validation)

### Why This Stack?

| Factor | Choice | Reason |
|---|---|---|
| **Backend** | Flask over Spring Boot | 70% less boilerplate, no compilation, instant reload |
| **Templates** | Jinja2 over React | No npm/build step, same-server rendering, simpler |
| **CSS** | Tailwind CDN | One `<script>` tag, no install, utility-first |
| **Database** | SQLite | Zero setup, single file, no server needed |
| **Auth** | Flask-Login | 5 lines to set up vs Spring Security's 50+ |

### Design Philosophy

Clean, medical-professional design. **White-dominant** layout with **blue borders**, **blue icons**, and **blue accent elements**. Minimal, calming, trustworthy aesthetic appropriate for a healthcare platform.

## 🔐 ENCRYPTION IMPLEMENTATION

### AES-256-GCM for Report Files

```python
# encryption.py
from cryptography.hazmat.primitives.ciphers.aead import AESGCM
import os

def generate_key() -> bytes:
    """Generate a random 256-bit AES key."""
    return AESGCM.generate_key(bit_length=256)

def encrypt_file(data: bytes, key: bytes) -> bytes:
    """Encrypt data with AES-256-GCM. Returns nonce + ciphertext."""
    nonce = os.urandom(12)
    ciphertext = AESGCM(key).encrypt(nonce, data, None)
    return nonce + ciphertext  # prepend nonce for storage

def decrypt_file(encrypted_data: bytes, key: bytes) -> bytes:
    """Decrypt AES-256-GCM data. Expects nonce (first 12 bytes) + ciphertext."""
    nonce = encrypted_data[:12]
    ciphertext = encrypted_data[12:]
    return AESGCM(key).decrypt(nonce, ciphertext, None)
```

### Storage Strategy

- Each report gets a unique AES-256 key stored in the `Report` model (base64-encoded)
- Encrypted file saved to `storage/reports/{uuid}.enc`
- On download: read encrypted file → decrypt with stored key → serve to user
- Only the patient who owns the appointment (and the doctor) can access the report

## 🎯 CORE FEATURES SPECIFICATION

### 1. Authentication System

- **Patient registration**: name, age, gender, contact, address, username, password
- **Login**: username + password → session-based auth
- **Role separation**: patients see patient routes, doctors are pre-seeded (no doctor registration needed)
- **Protected routes**: `@login_required` decorator on all dashboard/feature routes

### 2. Injury Management

- Patient submits injury with: body part (dropdown), description (text), is_critical (checkbox)
- System auto-generates recommendation based on body part
- Injuries are listed on patient dashboard with status indicators
- Critical injuries get a red warning badge

### 3. Doctor Matching

- Simple dictionary-based matching: body part → doctor specialty
- Show list of available doctors that match the injury's body part
- Display doctor info: name, specialty, availability slot, type (General/Specialized)
- Patient selects a doctor and picks an appointment time

### 4. Appointment Booking

- Patient books appointment with a matched doctor
- Appointment starts as PENDING
- Doctor can CONFIRM or CANCEL from their dashboard
- After doctor writes report, appointment becomes COMPLETED
- Patient sees appointment status updates on their dashboard

### 5. Report Generation & Encryption

- Doctor fills report form: diagnosis, treatment plan, optional file upload
- Uploaded files are encrypted with AES-256-GCM before saving to disk
- Report metadata saved to database with encrypted file path
- Patient can view report text and download decrypted file
- Only the owning patient and assigned doctor can access the report
